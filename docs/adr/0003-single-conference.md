# ADR 0003 — One conference per independent deployment

Accepted user decision A, 2026-10-15; implemented only within Phase 1.1b. Supersedes the shared-tenancy/global-account portions of ADR 0001/0002, original SPEC and membership/switch roadmap. Historical delivery reports remain historical. No Phase 1.2 approval.

Maintain one repository/version/template. Each instance has its own accounts, credential hashes, sessions, tokens, roles and business data, PostgreSQL, Redis, capture mail and eventual private storage. Same email in two instances denotes two unrelated accounts. Hosts never choose a database dynamically; no default organization/membership, global registry, cross-instance SSO or per-event source fork. Organizers remain descriptive/contact/receipt data. Within-conference ownership, role/track/assignment permissions and self-review exclusions still matter.

The existing auth schema already supports a local account namespace, so no schema migration or auth rewrite is justified. Retain Argon2, CSRF/Origin, safe cookies, rate limits, local audit/outbox and worker recovery. Remove only the unused tenant helper/fixture; retain actual runtime-role/transaction/constraint checks and add deployment isolation tests. No production RLS policy is removed or bypassed. Future role/resource policies must be explicitly authorized and tested.

Validated `CONFERENCE_NAME` and `PUBLIC_APP_ORIGIN` are minimal deployment settings; `/api/instance` exposes only `{conferenceName}` through contract/SDK/hook/props. No build-time VITE conference identity. The worker uses the same validated display name; token URLs remain encrypted outbox snapshots of canonical server origin. Editable/versioned conference settings, locale/contact configuration and CMS are future work, not a second settings authority here.

One versioned image can run Web/API/worker for both projects. Independent Compose project-scoped networks/volumes, nonprivileged process credentials and separate Redis services are the default test topology. Loopback published infrastructure ports are local development conveniences. Production must restrict them and provide deliberate TLS/proxy/ingress policy; no shared DB/Redis network or shared data mounts. Independent project names do not constrain host root/Docker admins or guarantee resource availability; shared-kernel and resource-exhaustion risks remain.

Different hostnames are essential: cookies are not port-isolated. HTTPS configuration retains `__Host-` Secure cookies; explicit local HTTP uses `dev-` cookies and single-level `*.localhost` for browser testing. Web ingress and non-health API routes check canonical Host; Origin/CSRF remain independent controls. Forwarded Host/IP never confers trust. A valid A session/token is invalid in B's database even if manually copied. TLS behavior is configuration-tested only; no production TLS claim.

Next edition means a fresh deployment with fresh secrets/accounts. Later whitelisted config export/import may reuse templates after date validation, never entire account/business DBs. Backup/restore is recovery of the same conference. Operators choose image tag/digest and migration/backup/recovery per instance; updating A never implicitly upgrades B. No central control plane or automatic upgrader is added.

No new dependency; framework/runtime pins remain unchanged. Existing Drizzle dependency is retained for the selected stack; retired fixture was its only direct query consumer and no speculative repository wrapper replaces it. The local test runner maps *.localhost to loopback for Node HTTP only; browsers follow actual canonical Mailpit links themselves.

References checked against implementation: [Compose project names](https://docs.docker.com/compose/how-tos/project-name/), [volume names are not project-scoped when explicitly named](https://docs.docker.com/reference/compose-file/volumes/), [RFC 6265 cookie isolation](https://www.rfc-editor.org/rfc/rfc6265.html), [Vite build-time environment replacement](https://vite.dev/guide/env-and-mode). Product scope is the user's decision, not inferred from these references.
