# ADR 0005 — Bounded site aggregate and public-only request rendering

Accepted 2026-10-15 for the user's Phase 1.3 request. The attached PHASE1_3_CONFERENCE_SITE_CODEX.md is acceptance guidance, not evidence of implementation or passing tests. One codebase / independently deployed conference remains the product boundary.

Use one singleton `site_state`, an incrementing draft version and immutable `site_publications`. A fixed schemaVersion 1 JSON document has four pages, two supported languages, typed dates/contact/identity, paragraphs/lists/limited links. No EAV, generic CMS, rich HTML/Markdown, plugins, arbitrary CSS/assets or remote URL fetch. Optional blocks have no fictional content. Existing dependency pins suffice; no dependency or env variable is added.

All site commands and private reads share the existing access-control fence: control row → actor user/session revalidation → site update. This deliberately serializes infrequent administration and avoids reverse lock order with access revocation. Publish additionally checks the existing five-minute password proof. A new credential epoch or permission cache would duplicate existing authority. `expectedVersion` protects first save, updates, publish and historical load. Unique source draft version makes repeat publish an exact no-op while current; stale versions conflict. Save/snapshot/pointer/required audit share one PG transaction. Runtime lacks UPDATE/DELETE on publications and audit; worker has no site-table grant. These local service/grant boundaries do not pretend to be resource RLS for future manuscripts.

Public loader selects pointer and document in one joined statement, binding all fields to one immutable publication despite Read Committed. No draft read or content cache. New reads after commit see the new version; already loaded pages are not live updates. No Redis site cache, background regeneration, CDN purge or WebSocket.

`effectivePublicSite` is the API/auth mail brand authority: published default-language identity or, only before first publication, the validated bootstrap CONFERENCE_NAME. DB failures become SERVICE_UNAVAILABLE and safe diagnostics, never fallback. Notification writes capture this resolved name in the existing outbox transaction; retries use it. Pre-upgrade NULL names use the former worker bootstrap-name behavior. Origin/from/provider credentials remain deployment configuration. No new worker query into private website settings.

Fastify public routes load the complete view model then call a Vite SSR artifact exporting a pure React renderer. This reuses `PublicSiteContent` in protected saved-version previews. `renderToStaticMarkup` emits full HTML without hydration/JSON scripts; auth/access/admin remain the existing SPA. Renderer imports are allowlisted separately and presentation may import contract **types only**; DB/config/SDK/hooks stay forbidden. The artifact bundles its existing React dependency so API needs no new React dependency. The browser build never imports the server entry. CSS uses the same tokens/styles. Production loads built artifacts, never Vite. `pnpm dev` builds the renderer before starting; after editing renderer/shared presentation in host dev, rerun `pnpm --filter @confsys/web build:public` to refresh public rendering.

All dynamic HTML/site DTO/private responses use no-store. CSP remains self-only without unsafe-inline. React owns HTML/meta encoding; sitemap XML escapes its trusted origin and enum paths. Text containing HTML is inert text, not an accepted HTML language. Links allow validated HTTPS without userinfo/backslash/whitespace, or explicit locale/page routes. Email links derive from validated typed email. Unknown routes/locales return actual 404; no generic SPA fallback.

Dates are Gregorian date-only strings, validated by exact round-trip and ordered lexically; never formatted through browser local time. Enabled languages require name and all page title/description fields. Missing optional text/list/link content falls back as a whole field to the default locale and marks that field's actual lang. Venue may remain explicitly unannounced. No duplicated registration/submission deadlines.

Migration 0005 is forward-only and additive to 0004. It adds no admin grants/account changes/bootstrap reset/session revocation. Existing publication history remains immutable; loading one produces a new draft, not a database rollback. Stop matching app processes for an instance upgrade, migrate separately, deploy a matched API/worker/Web image. Do not mix older clients or claim tested downgrade/backup restore. Repair by a reviewed forward migration. Existing pending mail/token/session compatibility is tested using synthetic prior-schema databases.

Mechanisms checked against [Vite SSR](https://vite.dev/guide/ssr), [React server rendering](https://react.dev/reference/react-dom/server/renderToString) and [PostgreSQL Read Committed](https://www.postgresql.org/docs/17/transaction-iso.html). Fixed pages, no-store and lock policy are project decisions. No search-engine indexing or ranking claim follows from HTML tests.
